# Часть 3. Тестирование

## Часть А. Теоретическая часть

### 1. В каких случаях тестирование не может полностью доказать корректность программы?

Можно назвать следующие случаи.

1. **Невозможность исчерпывающего тестирования.** Входных данных и состояний может быть бесконечно много. Пример: функция принимает вещественное число, невозможно проверить все значения.
2. **Тестирование показывает наличие ошибок, но не их отсутствие.** Даже если все тесты пройдены, могут остаться ошибки в непроверенных сценариях. Пример: программа работает на тестовых данных, но падает на экзотической комбинации.
3. **Ошибки в спецификации (требованиях).** Если требования неверны или неполны, тестирование не выявит этого, так как проверяется соответствие требованиям. Пример: программа корректно реализует неверную формулу.
4. **Недетерминированное поведение и параллелизм.** Гонки, ошибки, зависящие от времени, трудно воспроизвести. Пример: многопоточная программа может проходить тесты, но иметь редкие гонки.
5. **Ограниченность ресурсов и конфигураций.** Нельзя протестировать все ОС, компиляторы, оборудование.

### 2. Как выявляются противоречия в требованиях? Назвать 3 метода

1. **Ревью или инспекция требований.** Эксперты вручную проверяют требования на конфликты. Пример: одно требование "пароль не менее 8 символов", другое "пароль ровно 6 символов".
2. **Матрица трассируемости.** Сопоставление требований с тестами и друг с другом; пересечения выявляют конфликты.
3. **Моделирование или прототипирование.** Создание модели или прототипа помогает обнаружить логические противоречия при попытке реализации.
4. **Анализ сценариев использования (use cases).** Проверка, что все сценарии могут быть выполнены без конфликтов.
5. **Формальные методы.** Математические модели для проверки непротиворечивости.

### 3. Какие требования предъявляются к качественному тест-кейсу?

1. **Атомарность.** Тест-кейс проверяет одну вещь. Пример: тест сложения не должен также проверять умножение.
2. **Однозначность и понятность.** Шаги и ожидаемый результат чётко описаны. Пример: "Ввести 2+2, нажать =, ожидать 4".
3. **Воспроизводимость.** При повторном выполнении даёт тот же результат. Пример: тест не зависит от текущего времени или случайных чисел без фиксации seed.
4. **Независимость от других тестов.** Порядок выполнения не влияет на результат.
5. **Наличие предусловий и постусловий.**
6. **Покрытие позитивных и негативных сценариев.**
7. **Поддерживаемость.**

### 4. Что такое тест-план и какие разделы он содержит?

Тест-план это документ, описывающий стратегию, цели, ресурсы, график и подход к тестированию. Ключевые разделы:

1. **Цели и область тестирования (scope).** Что тестируется, что нет. Пример: тестируем модуль оплаты, не тестируем интеграцию с банком.
2. **Стратегия тестирования.** Виды тестирования (юнит, интеграционное, нагрузочное), критерии входа и выхода. Пример: сначала юнит-тесты, затем интеграционные.
3. **Ресурсы и роли.** Кто тестирует, оборудование, ПО. Пример: 2 тестировщика, стенд Windows 10.
4. **Расписание (timeline).** Этапы и сроки. Пример: юнит-тесты до 10 мая, интеграционные до 20 мая.
5. **Риски и меры их смягчения.** Пример: риск нехватки времени, приоритизация тестов.
6. **Критерии приёмки.** Когда тестирование завершено. Пример: 95% тестов пройдено, критических багов нет.

## Python. Поиск второго по величине элемента списка

### Файл `second_largest.py`

```python
def second_largest(lst):
    """
    Возвращает второй по величине уникальный элемент списка.
    Если такого элемента нет, возвращает None.
    """
    if len(lst) < 2:
        return None

    first = second = float('-inf')

    for x in lst:
        if x > first:
            second = first
            first = x
        elif x > second and x != first:
            second = x

    if second == float('-inf'):
        return None

    return second
```

### Чек-лист

- пустой список;
- список из одного элемента;
- все элементы одинаковы;
- два элемента;
- отрицательные значения;
- дубликаты;
- положительные значения;
- смешанные значения;
- уже отсортированные по возрастанию или убыванию.

### Тест-кейсы

| № | Вход | Ожидаемый результат |
|---|------|---------------------|
| 1 | `[1, 2, 3, 4, 5]` | `4` |
| 2 | `[5, 5, 5, 5]` | `None` |
| 3 | `[]` | `None` |
| 4 | `[42]` | `None` |
| 5 | `[-10, -5, -20, -5]` | `-10` |
| 6 | `[3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5]` | `6` |
| 7 | `[2, 2, 1]` | `1` |

### Файл `test_second_largest.py`

```python
import unittest
from second_largest import second_largest


class TestSecondLargest(unittest.TestCase):
    def test_regular(self):
        self.assertEqual(second_largest([1, 2, 3, 4, 5]), 4)

    def test_all_same(self):
        self.assertIsNone(second_largest([5, 5, 5, 5]))

    def test_empty(self):
        self.assertIsNone(second_largest([]))

    def test_single(self):
        self.assertIsNone(second_largest([42]))

    def test_negative(self):
        self.assertEqual(second_largest([-10, -5, -20, -5]), -10)

    def test_duplicates(self):
        self.assertEqual(second_largest([2, 2, 1]), 1)

    def test_unsorted(self):
        self.assertEqual(second_largest([3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5]), 6)


if __name__ == '__main__':
    unittest.main()
```

Запуск:

```bash
python -m unittest test_second_largest.py
```

## C++. Функция `sumEven()` и Google Test

### Файл `sum_even.h`

```cpp
#pragma once

#include <vector>

inline int sumEven(const std::vector<int>& arr) {
    int sum = 0;
    for (int x : arr) {
        if (x % 2 == 0) {
            sum += x;
        }
    }
    return sum;
}
```

### Чек-лист

- пустой массив;
- только чётные числа;
- только нечётные числа;
- смешанные значения;
- отрицательные чётные;
- нули;
- большие числа;
- один элемент.

### Тест-кейсы

| № | Вход | Ожидаемый результат |
|---|------|---------------------|
| 1 | `{}` | `0` |
| 2 | `{2, 4, 6}` | `12` |
| 3 | `{1, 3, 5}` | `0` |
| 4 | `{-2, -4, 3}` | `-6` |
| 5 | `{0, 1, 2, 0, 3}` | `2` |
| 6 | `{2, -2, 2}` | `2` |
| 7 | `{1, 0, 1}` | `0` |

### Файл `test_sum_even.cpp`

```cpp
#include <gtest/gtest.h>
#include "sum_even.h"

TEST(SumEvenTest, EmptyArray) {
    EXPECT_EQ(sumEven({}), 0);
}

TEST(SumEvenTest, OnlyEven) {
    EXPECT_EQ(sumEven({2, 4, 6}), 12);
}

TEST(SumEvenTest, OnlyOdd) {
    EXPECT_EQ(sumEven({1, 3, 5}), 0);
}

TEST(SumEvenTest, NegativeEven) {
    EXPECT_EQ(sumEven({-2, -4, 3}), -6);
}

TEST(SumEvenTest, WithZeros) {
    EXPECT_EQ(sumEven({0, 1, 2, 0, 3}), 2);
}

TEST(SumEvenTest, Mixed) {
    EXPECT_EQ(sumEven({2, -2, 2}), 2);
}
```

Пример сборки при установленном Google Test:

```bash
g++ -std=c++17 test_sum_even.cpp -lgtest -lgtest_main -pthread -o test_sum_even
./test_sum_even
```
